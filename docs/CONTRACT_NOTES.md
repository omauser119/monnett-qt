# Особенности реализации контрактов

Снимок: 18 октября 2026 года. Первичные источники: локальный справочник Android 1.5.0 и обе официальные OpenAPI. Официальные prod/dev ответы имеют одинаковый SHA-256 `57d625669defd53e9d833116f677b34af61ac9faa5579553e6893b89f2696e56`.

- Все REST-пути включают `/api`. URL собирается через `setPath`, чтобы ведущий `/` не удалял этот префикс. Параметры пути кодируются как отдельные сегменты; массивы query используют повторяющиеся ключи.
- Обёртка `success` снимается только при наличии этого поля. При `success=false` HTTP 200 всё равно считается ошибкой. При успехе приоритет имеют `payload`, затем `data`. Структуры с `data` и `meta` без поля `success` остаются целыми.
- `/refresh` получает JSON-строку, не объект `{refresh_token: ...}`. Параллельные 401 разделяют одно обновление. Поздний 401 старого JWT не запускает второе обновление, если JWT уже сменился.
- Повтор допускается после явного HTTP 401 и успешного refresh. Автоматических повторов записей после timeout, 429 или 5xx нет. Это особенно важно для legacy toggle follow/block/like.
- Новые методы follow/block/comment-like/pin используют идемпотентные POST/DELETE вместо toggle. Старые варианты сохранены в каталоге.
- У UUID и числового ID разные назначения. V1 посты, комментарии, подписки и блокировки используют public UUID; legacy-профиль, `users/{id}/posts` и legacy-списки связей используют числовой `id`. Они не подменяются друг другом.
- Новый create возвращает UUID прямо в `payload` по официальной схеме; реверс ожидает `postId`/`post_id`. Поддерживаются обе формы. Файлы отправляются в multipart `file`, `postId`, `mediaIndex`. Аватар использует отдельную legacy-загрузку `files`.
- Дополнительные поля нового `InitializePostRequest` (например, `title`, `share_with`, `is_mature`) доступны в редакторе. Типизированные UI-поля заполняют аудиторию по перечислению `PUBLIC`, `FOLLOWERS`, `CLOSE_FRIENDS`.
- OpenAPI показывает `FieldUpdate*` для профиля как объект с `present/value/missing`. Нативный редактор отправляет плоские значения, подтверждённые сетевым сериализатором Android. В каталоге исходная серверная схема сохранена. Это место требует проверки на авторизованном сервере.
- Discover понимает как `items` с `post/transition`, так и современный ответ `posts`. Timeline раскрывает группы `timeline[].posts`. Переходы не отображаются как пустые посты.
- Восстановленные и официальные пути сопоставляются с нормализацией только имён path-параметров. Поэтому `{postId}` и `{id}` не дают дубликата. Уникальные legacy `GET /api/posts/{postId}/likes` и `POST /api/{storyId}/view` остаются в каталоге.
- Matrix homeserver и отдельный accessToken берутся из `/v1/app/msg/session`. Monnett JWT не отправляется в homeserver; REST-токен также не отправляется на CDN изображений. Криптографией и encrypted attachments занимается libQuotient.
- Сессия SDK использует сохранённый для аккаунта Matrix device ID. Смена аккаунта закрывает страницу сообщений и останавливает её sync. Окна, выполняющие операции аккаунта, блокируют переключение родительского окна, пока они открыты.
- Admin/webhook/JobRunr отфильтрованы при генерации ресурсов; транспорт дополнительно запрещает эти маршруты. Каталог не позволяет произвольные внешние URL с Bearer-токеном.

## Где искать код

| Задача | Файлы |
| --- | --- |

| Обновление API и матрицы покрытия | `tools/update_api.py` |

## Проверка с реальным аккаунтом

Для проверки живого сервера войдите в самом приложении. Пароли и токены не нужны в issue, shell history или исходниках. Проверьте вход, `/user`, переключение аккаунтов, текстовую публикацию, файл, лайк, ответ на комментарий и DM с другим аккаунтом. Тестовые изменения удобно выполнять на dev через скрытый жест добавления аккаунта. Синтетические тесты не заменяют такую проверку.
